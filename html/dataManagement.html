Data management

Data folder, DDK family, ICGEM access (v2.4.1)

One persistent storage location, all released DDK filters, and the ICGEM model catalogue.

shLowLevel.testDataDir

Resolves the shipped sample/fixture folder (v3.26.2): the SHX_TESTDATA_FOLDER environment variable first, then the TestDataFolder preference (setup_shAnalysis(TestDataFolder=...), persistent), then the in-repo tests/test_data. One resolver serves three consumers: toolbox code (readDDK("DDK3") finds the shipped Wbd sample), the demos, and the test suites (whose tests/shxTestDataDir is a thin delegate). Point it at a data drive to keep fixtures out of every checkout; CI obtains them from the orphan branch testdata instead.

setup_shAnalysis(TestDataFolder = "E:\DATAPOOL\GravityField\test_data")
W = shLowLevel.readDDK("DDK3");     % resolves through testDataDir

shLowLevel.dataFolder

shLowLevel.dataFolder("D:/geodata/shAnalysis")   % set once, persists across sessions
shLowLevel.dataFolder()                    % query (default: <toolbox>/data)
shLowLevel.dataFolder("reset")

All fetchers store beneath it: itsg_series/, DDK/, icgem/. Point it at a shared network folder to reuse downloads across machines.

shLowLevel.fetchDDK / shLowLevel.readDDK("DDK<n>")

shLowLevel.fetchDDK(1:8);                  % ~10 MB each, skips existing
W5 = shLowLevel.readDDK("DDK5");           % name resolution against dataFolder
gF = g.applyDDK(W5);

All eight released filters (Kusche 2007; Kusche et al. 2009), strong → weak: DDK1 (a=1e14) … DDK8 (5e9); regularization a·l⁴. DDK3 ships inside the toolbox and never needs fetching; an unfetched name errors with the fetch hint (shLowLevel:readDDK:notFetched). Filenames come from one mapping (shLowLevel.ddkNames), verified against the repository.

shLowLevel.listICGEM / shLowLevel.fetchICGEM

T = shLowLevel.listICGEM();                        % 180+ static models: name,
sortrows(T, 'year', 'descend')              % year, degree, data, url
f = shLowLevel.fetchICGEM("EGM2008");              % -> dataFolder/icgem/*.gfc
g = shCoefficients.read(f);

The static catalogue is parsed from icgem.gfz.de/tom_longtime (parser fixture-tested offline against a saved page). Name resolution: exact match, else unique prefix; ambiguity errors with candidates. Type="temporal" (reworked v2.4.2) returns the full temporal catalogue parsed from the series-page links of /sl/temporal — every series of every center (~70+ across the groups 01_GRACE, 02_COST-G, 03_other, 04_SLR) with columns group, center, series, path, url (series page) and zip (whole-series ZIP, hundreds of MB). Passing a catalogue path into Series= lists the individual files of that series (name, url) — single monthly .gfc files download directly via websave; the earlier "JavaScript-only" caveat is obsolete. Example:

T = shLowLevel.listICGEM(Type="temporal");             % 70+ series, all centers
F = shLowLevel.listICGEM(Type="temporal", ...
        Series="03_other/ITSG/ITSG-Grace2018/monthly");
websave("m1.gfc", F.url(1));                    % one monthly file

For ITSG monthly files shLowLevel.fetchITSG remains the convenient route, whose default target is dataFolder/itsg_series.

Safe swaps: why downloads land atomically v3.1.4

Every shLowLevel.fetch* function downloads to <target>.part, parses the fresh file to verify it, and only then swaps it into place. A half-downloaded or corrupt file therefore never replaces a good one, and an interrupted fetch is resumable.

The swap itself goes through shLowLevel.safeMove, which retries with exponential backoff (0.25/0.5/1/2/4 s by default). This is not defensive padding: on Windows an antivirus or a cloud-sync client (OneDrive, Dropbox, DLP agents) opens a just-written file to scan it and holds it briefly, so a plain movefile reports a download failure for a file that downloaded perfectly. Each attempt verifies that the destination exists and the source is gone rather than trusting the status flag, because synced and network volumes have been seen reporting success too early.

n = shLowLevel.safeMove(tmpf, target);            % n = attempts used
n = shLowLevel.safeMove(tmpf, target, Retries = 8, Pause = 0.5);
If a fetch still fails with shLowLevel:safeMove:locked, the file is fine — the folder is the problem. Exclude the data folder from on-access scanning, or point shLowLevel.dataFolder at a location outside the synced drive.

GRAVIS Level-2B: the SHM format v3.3.0

GravIS Level-2B products — monthly solutions, the mean field, the ICE-6G_D (VM5a) GIA rate model, the low-degree and geocenter tables — are not in ICGEM .gfc layout. They use a YAML header followed by keyword records:

GRCOF2  n  m  C  S  sigC  sigS  t0  t1  flags     a FIELD
GRDOTA  n  m  Cdot  Sdot                          a RATE [1/yr]

shLowLevel.readSHM reads both, transparently through gzip, taking GM and the reference radius from the header. The keyword is the only thing distinguishing a rate model from a field, which is why a rate must never be read by a parser that assumes a field.

gia = shLowLevel.readSHM("GRAVIS-2B_..._GIA_ICE-6G_D_VM5a_0001.gz", Nmax = 96);
g   = shCoefficients(gia.C, gia.S, GM = gia.GM, R = gia.R);
[ts, rep] = shLowLevel.standardChain(folder, GIA = g, Filter = "DDK3");
A GIA model at degree 256 against a solution at 96 wastes memory and time; pass Nmax= to truncate while reading.
