designFilter — a DDK-class filter from your own covariances

The released DDK filters are built from one particular center's normal equations at one particular release. shLowLevel.designFilter performs the same construction against your solution's error information, and emits the result in the exact block format readDDK produces — so it drops into applyDDK, g.applyDDK and standardChain(Filter=W) unchanged.

[W, info] = shLowLevel.designFilter(SigmaC, SigmaS, Name=Value)

What it computes

Per order/parity block, the Wiener-type decorrelation operator

W = (N + Alpha * inv(S))^-1 * N

where N is the normal matrix (from the formal sigmas as a diagonal, or from a full covariance via Noise=) and S is the signal covariance (a Kaula-type degree rule by default, or your own model via DegVar= / Signal=). This is the same structure the published DDK filters have: anisotropic, order-dependent, strong on the near-sectorial coefficients where the striping lives.

Options

OptionDefaultMeaning
Alpha1regularization weight. Larger = stronger smoothing (DDK1-like), smaller = weaker (DDK7+). This is the knob you turn.
Kaula1e-5signal RMS per coefficient, K/n2. Ignored when DegVar or Signal is given.
DegVar[](nmax+1 x 1) per-degree signal variance; overrides Kaula.
Noise[](P x P) full noise covariance in shIndex ordering; overrides the sigmas.
Signal[](P x P) full signal covariance, same ordering.
Idx[]the shIndex struct — required whenever Noise or Signal is used.
MinDegree2first filtered degree; below it W passes coefficients through unchanged.
Name"designFilter"stored in W.name, so filtered histories stay readable.
Noise and Signal are COVARIANCES, not sigmas. Passing standard deviations where a variance is expected produces a filter that looks entirely plausible and smooths by the square root of what you intended. If you have sigmas, pass them as SigmaC/SigmaS and let the function square them.

Examples

% from a solution's own formal errors
g  = shCoefficients.read("ITSG-Grace2018_n60_2008-04.gfc");
W  = shLowLevel.designFilter(g.sigmaC, g.sigmaS, Alpha = 1);
gF = g.applyDDK(W);

% from a released full covariance (SINEX)
snx = shLowLevel.readSINEX("ITSG-Grace2018_n96_2008-04.snx");
idx = shLowLevel.shIndex(96);
W2  = shLowLevel.designFilter(g.sigmaC, g.sigmaS, Noise = snx.M, Idx = idx);

Checking the result

INFO reports alpha, mode ("diagonal" | "fullcov") and gainRange, the min/max eigenvalue over all blocks. For SPD inputs every eigenvalue lies in (0, 1): a gain above 1 means the filter would amplify a direction, which never happens with a consistent covariance and is the first thing to check if a result looks wrong. As Alpha tends to 0 the operator tends to the identity. A useful sanity step is to plot the gains over the (degree, order) triangle and compare them against a released DDK — they should have the same anisotropic character.
