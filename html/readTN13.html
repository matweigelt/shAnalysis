readTN13

Read a GRACE/GRACE-FO TN-13 geocenter (degree-1) file and complete the standard processing chain: GSM coefficients + applyTN14 (C20/C30) + addDegree1 (C10/C11/S11). Without degree 1, EWH and mass grids are systematically biased.

Syntax

tn = shx.readTN13(filename)              % .txt or .gz
g1 = g.addDegree1(tn)                    % nearest epoch within Tolerance=0.05 yr
g1 = g.addDegree1("TN-13_GEOC_CSR_RL06.txt")

Format

Official TN-13 products (JPL/CSR/GFZ) with data lines

GRCOF2  n  m  Clm  Slm  Clm_sig  Slm_sig  begin  end

n = 1, m = 0/1, epochs yyyymmdd.hhmm. Line pairs sharing an interval are combined into one monthly record with the interval mid-point as epoch (decimal years via shx.icgemDate2Year).

Outputs

FieldSizeDescription
epoch(K,1) doubleinterval mid-points [decimal years]
C10, C11, S11(K,1) doubledegree-1 Stokes coefficients
sigC10, sigC11, sigS11(K,1) double1-sigma formal errors
t0, t1(K,1) doubleinterval bounds [decimal years]
Verified against real data. The parser is validated against a real GFZ TN-13 (RL06.3, 2002-04 – 2026-04): 256 months, 512 perfectly paired GRCOF2 lines in exactly the layout above (9 columns; a 10th solution-flags column mentioned in the header does not occur in the data and would be ignored). The file ships as a fixture in tests/test_data/TN-13_GEOC_GFZ_RL06_3.txt; the robustness suite checks hard expected values (first/last month, epoch conversion to 1e-12), the full degree-1 chain on the real ITSG 2008-04 solution, the gzip branch, and that the GRACE↔GRACE-FO gap (2017.39–2018.41) is visible in the sampling — the motivation for ts.dropNaN()/select(). Non-GRCOF2 lines (including the yaml header's key_name : GRCOF2) are skipped safely. JPL/CSR TN-13 variants share this record format per the GRACE Level-2 handbook.
