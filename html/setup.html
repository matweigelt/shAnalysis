Functionv2.5

setup_shAnalysis

One-call setup: adds the toolbox to the MATLAB path (temporarily or permanently) and orchestrates the data downloads in cumulative levels. Re-running is idempotent — existing files are skipped, every download is verified by parse before it is accepted, and an offline machine still gets a working path setup plus the shipped fixtures.

Syntax

setup_shAnalysis                        % path, this session only
setup_shAnalysis(Permanent = true)      % path + savepath
setup_shAnalysis(Download = "core")     % + TN-14/TN-13 (~250 KB)
setup_shAnalysis(Download = "filters", DDK = [2 3 5])
setup_shAnalysis(Download = "starter")  % + ITSG starter months
setup_shAnalysis(Download = "all")      % + the COMPLETE monthly archive
s = setup_shAnalysis(DryRun = true, Download = "starter")   % plan only

Download levels (cumulative)

leveladdssizebackend
"none"path only (default)——
"core"GSFC TN-14 (C20/C30) + TN-13 geocenter files (GFZ/CSR/JPL) — the low-degree completion chain~250 KBshLowLevel.fetchTN
"filters"anisotropic DDK decorrelation matrices (subset via DDK=, default 3)~10 MB eachshLowLevel.fetchDDK
"starter"ITSG monthly-solution starter set (default: the n96 companions of the shipped n60 fixture months, 2008-04 and 2025-12)~1 MB/monthshLowLevel.fetchITSG
"all"starter + the complete ITSG monthly archive, 2002 → present (v3.27; existing files skipped, so re-runs resume)several GBshLowLevel.fetchITSG

Downloads land in shLowLevel.dataFolder() subfolders (TN/, DDK/, itsg_series/). Point shLowLevel.dataFolder(PATH) at a shared location first to reuse downloads across machines.

Path handling

Already-on-path is detected (no duplicate entries). With Permanent=true, savepath persists the path; if that fails (no write permission on pathdef.m — common on managed machines) the session path stays set and a warning explains the startup.m alternative.

Verification & failure handling

shLowLevel.fetchTN parses every file with shLowLevel.readTN13/readTN14 before accepting it — a truncated download or an HTML error page never survives (deleted + reported). Each level runs in isolation: failures are collected in summary.failed and the remaining levels still run. summary.ok is true iff nothing failed.

DryRun

DryRun=true returns the full action plan with zero side effects: no path change, no folder creation, no network. Contract-tested.

Opt-in test data v3.8.2

Two checks need data far too large to ship as fixtures, so they read an environment variable and filter themselves out when it is unset. Pass the paths to setup_shAnalysis and it exports them for the session:

setup_shAnalysis(SeriesFolder = "D:/grace/itsg", ...
                 MasconFile = "D:/grace/GRCTellus_JPL.nc");
VariableEnablesData
SHX_SERIES_FOLDER the trend regression in testScience a folder of monthly .gfc files, > 24 epochs, GSM level — fetchITSG or fetchICGEM
SHX_MASCON_FILE the readMascon check against a real product CSR (no login), GSFC, or JPL PO.DAAC (free Earthdata login)
This is not tidiness. The fixture suite cannot see the class of failure that only appears on real data of real length: three bugs surfaced the first time the toolbox ran against a full 24-year series, and the mascon reader's dimension order was only settled by a real product file. Neither variable is required — without them the suite runs complete and both tests report as filtered rather than passing silently.

setenv lasts for the session only; put the same lines in your startup.m to keep them. SHX_SERIES_FOLDER is deliberately not wired to the persistent data folder: a routine acceptance run must never reach for a network or archive drive, so pointing at that data stays an explicit decision.
