shAnalysis — overview

Version 3.17.0 — the toolbox version is defined in Contents.m and reported by shLowLevel.version and MATLAB's ver.

Spherical harmonic (Stokes coefficient) analysis for GRACE/GRACE-FO, GOCE, and static gravity field models. Three user-facing classes cover the whole chain; every numerical building block lives in the +shLowLevel package and is callable directly. Base MATLAB only — no toolboxes.

v3.0.0 was a breaking release: the package was renamed +shx → +shLowLevel (error identifiers shLowLevel:*), and the compat/ folder with the v1 function API was removed. Call shLowLevel.shReadGFC(...) instead of shReadGFC(...), or use the classes. Run shLowLevel.version for the installed version; the API reference is generated from the source on every release.

The three classes

ClassScope
shCoefficientsone coefficient set: read/write, arithmetic, TN-14, destriping, Gaussian smoothing, spectra, synthesis, gfct evaluation
shSeriestime series: mean field, climatology, GAX restore, classic chain per epoch, tvANS filter, basin averages with exact deconvolution
shClimatologybias/trend/annual/semi-annual model: components, evaluation, amplitude/phase maps

Typical session

ts  = shSeries.read("GSM-2_*.gfc", Truncate=60);
ts  = ts.restore(shSeries.read("GAD-2_*.gfc", Truncate=60));
dts = ts - ts.mean;
[clim, resid] = dts.climatology(Robust=true);
tsA = dts.destripe(minOrder=6).gaussian(300);        % classic
[tsF, op] = dts.filter("tvANS");                     % optimal
avg = tsF.basinAverage(B, Deconvolve=true, Op=op);

Validation

runAllTests executes four suites: numerical correctness (golden and analytic values), API contract (error identifiers, immutability, dimensions), robustness (NaN stacks, degenerate basins, corrupted files, poles) and performance benchmarks (with a Legendre-cache speedup assertion). The v1 legacy suite went with compat/ in v3.0.0. Every numerical method was cross-validated in Python (numpy/scipy) before the MATLAB implementation, and every field failure since has been converted into a fixture plus a contract test. The suite is CI-safe: all fetchers run offline against fixtures.

Policy: no physical tables are hardcoded — Love numbers, TN-14 corrections etc. are always user-supplied and parsed, never assumed.
